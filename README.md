# 跨行債權申報與彙整平台

> 跨銀行「前置調解**債權申報與彙整**」協作平台 —— 讓同一件債務調解案中的多家債權銀行，各自安全申報自己的債權、全員確認後一次彙整，最後由主辦回報案件成立／不成立。

本專案為 **2026 富邦債管聯合試辦**的技術試辦系統，屬概念驗證／試辦（POC）性質。目前版本 **v0.3**（流程改版：債權申報與彙整、無還款管理）。

---

## 這個平台在解決什麼問題？

當一位債務人同時積欠多家銀行、進入「前置調解」程序時，實務痛點是：

- **資料分散**：各銀行各自持有債權明細，缺乏一致、可信的彙整管道。
- **反覆對帳**：金額須在銀行之間來回確認，容易出錯、耗時。
- **易被錨定**：若能先看到別家的數字，容易相互參照而失真。

本平台把流程收斂到單一系統：**各行封閉申報自己的債權 → 全員確認後一次揭露、產出債權彙整表 → 主辦回報結果**，並保留完整稽核軌跡。

> **範圍界定**：本系統只做「跨行債權資訊傳遞與彙整」。**不含**還款計劃／逐月還款／結清等還款管理，**不處理**法定期限／時效，債務人與法院**全程在線下**、無系統互動。

---

## 核心概念與流程

平台圍繞「**案件（Case）**」運作，一件案件即一位債務人的一次調解，以 **(法院代碼 + 公文文號)** 唯一辨識（不儲存債務人個資）：

```
主辦起案 + 邀請（依法院公文）
   → 發布，開放各行「封閉申報」
   → 各行（含主辦）自填自己的債權並確認（申報期間只看得到自己的）
   → 全員確認 → 一次揭露、產出「債權彙整表」（參與行互相可見）
   → 主辦線下與債務人確認後，回報「成立 / 不成立」（終態）
```

- **封閉申報**：申報期間各行只見自己的數字、確認進度與參與行名單；**全員確認後才一次揭露**，防止相互錨定。
- **各行自填自己的**：每家（含主辦）只為自己的數字負責，不代填、不互相審批。
- **疑義迴圈**：揭露後任一參與行可標記疑義（附理由）→ 全案退回、全員重新確認。
- **回報結果**：成立／不成立是主辦**線下與債務人確認後的結果登錄**（系統存證、**非系統裁定**）；結案為**終態、完全鎖死**。

---

## 角色

- **最大債權行（主辦）**：起案、邀請/移出參與行、填報自己的債權、發布、回報成立／不成立。
- **其他債權行**：填報自己的債權、確認／撤回確認、拒絕參與（非本案債權人）、揭露後標記疑義。
- **平台管理員（開發商）**：帳號與機構治理；**只見案件狀態與進度，不見任何金額**（平台對案件內容全盲）。
- **平台稽核**：全案唯讀，**可見全部**（含各行明細），供監督。

> 「主辦／其他債權行」是**因案動態認定**：同一銀行帳號，在自己建立的案件是主辦，在別人邀請的案件就是其他債權行。

---

## 主要特色

- 🏦 **多銀行協作**：以主辦／其他債權行的角色分工，貼合前置調解實務。
- 🔒 **封閉申報＋一次揭露**：申報期各行只見自己，全員確認才揭露，避免錨定。
- 🕵️ **平台全盲、稽核可見**：平台管理員只見狀態不見數字；獨立稽核角色可見全部。
- 🔐 **後端強制權限（Server-side RBAC）**：可見範圍與可執行動作一律由後端把關。
- 🔑 **管理員建立＋啟用碼啟用**：無公開自助註冊，降低冒名風險。
- ♻️ **疑義可回溯 + 版本化**：每一輪揭露皆留申報快照，退回重確認全程留痕。
- 🛡️ **終態鎖死**：結案後不可更正、不得以同文號新建；回報採兩段式防呆。
- 🧾 **完整稽核軌跡**：申報、確認、撤回、揭露、疑義、回報等關鍵事件皆留存。
- 💰 **金額精度**：金額以 `Decimal(21,4)` 儲存，避免浮點誤差。

## 技術架構概觀

| 層 | 技術 |
|---|---|
| 前端 | React 18 + TypeScript + Vite 5 + Tailwind CSS 3 + React Router 6 + Zustand |
| 後端 | Fastify 4 + Prisma 5 + Zod（JWT、bcrypt、rate-limit） |
| 資料庫 | PostgreSQL 16 |
| 部署 | Docker（db + api + web + Caddy 反向代理／自動 HTTPS） |

```
├── src/                 前端（React）
├── backend/             後端（Fastify + Prisma）
│   └── prisma/          資料庫 schema、migrations、seed
├── docs/                系統文件
├── docker-compose.fullstack.yml   全棧一鍵部署
└── Caddyfile            反向代理設定
```

## 案件狀態機

| 狀態 | 意義 |
|---|---|
| `DRAFT` | 主辦起案＋邀請，尚未發布 |
| `PENDING_CONFIRMATION` | 封閉申報中：各行自填並確認自己（含主辦） |
| `PENDING_OUTCOME` | 全員確認、已揭露、產出債權彙整表，待主辦回報 |
| `ESTABLISHED` | 已回報成立（終態、鎖死） |
| `NOT_ESTABLISHED` | 已回報不成立（終態、鎖死） |
